This page covers common agent lifecycle operations in the dashboard, with the [CLI](/quickstart), and over the API. CLI examples assume you have run `omnara login` and `omnara config select`; API examples use a [bearer token](/api/authentication):

```bash
export OMNARA_API="https://api.omnara.com/v1"
export BASE="$OMNARA_API/orgs/$ORG/projects/$PROJ"
```

Create an agent from a [config](/agents/configuration), or from a [profile](/agents/configuration#profiles) if you want the launch tied to a named template.

  - **From profile** — pick an existing [profile](/agents/configuration#profiles); the launch uses its current config.
  - **Builder** — a form for instruction, model, machine sources, tools, skills, and MCP servers, with a live YAML preview.

### Attach apps and an initial input atomically

The create-agent API accepts `tools` and `interaction_handlers`
alongside the pinned `config`. They use the same names and capability selections as
ordinary config authoring. Derivation adds missing entries and preserves existing
entries as a whole, including explicit disabled tools. The base's pinned model
and other identities are retained.
When `profile` is supplied, the base `config` must be its current config or a
historical version of that profile.
The separate `subscriptions` array attaches app-owned conversations to the new
agent, using `app_id`, `type`, `conversation` and optional `events`. Subscriptions
alone leave the pinned config unchanged. Ordinary API attachments do not establish
sending context: tools take explicit destination arguments, and handler selection
always takes a complete destination. Only provider and scheduled launches bind
app-agent context automatically.
Adding tools, handlers or subscriptions requires project management permission; operating an existing
config requires only agent operate permission.

Use `initial_input` instead of `message` to supply text blocks with an attributed
actor. This example selects a GitHub read tool and subscribes to one PR without changing the
profile. The saved GitHub app is named `reviews`:

```json
{
  "config": "acfg_mv4qtrwz3jehcyd5n6a2bfgik7",
  "tools": {
    "app__reviews__read": {}
  },
  "subscriptions": [{
    "app_id": "YOUR_GITHUB_APP_ID",
    "type": "pull_request",
    "conversation": {"repository_id": 123456, "pull_request": 42},
    "events": ["discussion_comment", "review_comment", "commit"]
  }],
  "initial_input": {
    "content_blocks": [{"type": "text", "text": "Review pull request 42."}],
    "actor": {"provider_tenant_id": "review-service", "provider_user_id": "customer-7"}
  }
}
```

User-authenticated requests omit `actor`; API keys may supply an external actor.
Initial input supports queued text blocks; send inline media through the agent
input endpoint after launch.

The derived config, agent, subscriptions and initial input commit together.
A failure leaves none of those writes. The profile stays unchanged. Supply an
`Idempotency-Key` to make retries safe: the first success returns `201` with the
launch envelope, and reusing the key within the project returns `200` with only
the current agent. The retry body is not applied, even if it has changed or an app
reference has since been deleted.

## Find agents

The project's **Agents** page lists active agents; click one to open its conversation. `omnara agents list` and the API return active agents newest first; fetch one by ID with `omnara agents get {agent-id}`. Archived agents are omitted from the list but remain retrievable by ID.

<Info>
For full schemas and playground see: [List agents](/api-reference/endpoints/agents/list-agents) and [Get agent](/api-reference/endpoints/agents/get-agent).
</Info>

## Stop current work

Stopping cancels the agent's current turn, pending tool calls, and open interactions. The agent and its conversation remain available; the next input starts a new turn.

<Tabs>
<Tab title="API">
  <AgentsCancel />

  The response includes `affected: true` when work was canceled. `affected: false` means the agent was already idle, so the request is safe to repeat.

  <Info>
  Full schema and playground: [Cancel agent](/api-reference/endpoints/agents/cancel-agent).
  </Info>
</Tab>
<Tab title="Dashboard">
  While the agent is working, the composer shows **Stop agent** — click it. The button disappears when the agent is idle.
</Tab>
</Tabs>

## Archive an agent

Archiving retires an agent. It deletes its app subscriptions, stops current work, drops queued inputs, releases machine bindings, and deletes pooled machines created for the agent. The agent leaves active listings, but its event history remains available by ID.

Machines you connected yourself, configs, and profiles are not deleted.

<Tabs>
<Tab title="API">
  <AgentsArchive />

  The response returns the agent with `state: "archived"`. Repeating the request is safe.

  <Info>
  Full schema and playground: [Archive agent](/api-reference/endpoints/agents/archive-agent).
  </Info>
</Tab>
<Tab title="Dashboard">
  On the **Agents** page, open the row's actions and click **Archive**.
</Tab>
</Tabs>

There is no unarchive. Launch a new agent when you need to continue with fresh work.
