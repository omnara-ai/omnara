Building an agent is trivial. Running one in production isn't. An agent your product or team can actually rely on is a service: it needs hosting, team access, integrations, MCP servers, durability, and rules about what it's allowed to do.

Omnara provides that service. Define an agent, launch it, and Omnara runs the loop — execution environments, model calls, tools. The API is stateful: it stores the conversation, so new input resumes the agent where it left off.

Omnara is also designed to outlive any process or machine where its agents run, meaning crashes, restarts, or days-long execution are normal operation, not failure modes.

## How it fits together

1. An **organization** owns projects, secrets, models, and machines
2. A **project** scopes agents and the grants they can use
3. An **agent** is one running instance: its conversation, tool calls, and history
4. You send **inputs**, stream **events**, and resolve **interactions** when the agent needs you
