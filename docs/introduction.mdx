An agent your product or team can rely on is a service. It needs hosting, user and team access, integrations, durability, and clear rules about what it's allowed to do.

Omnara provides that service and makes it accessible through a console and stateful API. Conversations live in durable state, turning agents into durable API objects you can launch, stream, steer, and audit.

## Define, launch, converse

Most workflows follow three steps:

1. **Define** — use the console or write a small YAML config: an instruction, a model, and the tools the agent may use.
2. **Launch** — create an agent from that config. The agent starts working immediately.
3. **Converse** — stream its events live, send follow-up input, and resolve the approvals and questions it raises.

## How it fits together

1. An **organization** owns the shared resources: projects, secrets, model providers, machines.
2. A **project** scopes agents and the grants that decide which shared resources they may use.
3. An **agent** is one durable conversation with its config, tool calls, and history.
4. You send **inputs**, stream **events**, and resolve **interactions** when the agent needs you.

[How Omnara works](/how-omnara-works) walks through this object model in detail.
