This single-machine POC was tested on Windows Server 2022 x64. It runs the API, worker, maintenance, migrations, and embedded dashboard without Docker or a Linux VM. The machine daemon (`omnarad`) is separate and is not included.

Use PostgreSQL because Omnara requires PostgreSQL 18+; SQL Server cannot replace it. Garnet provides a native Windows Redis-compatible server with Lua and persistence. RustFS is the S3 store used by Compose; its [Windows build is for development and debugging](https://docs.rustfs.com/en/installation/windows), which is suitable for this POC. IIS fronts the embedded dashboard and API without changing other sites' proxy settings.

## 1. Prepare Windows and the native dependencies

Use a local NTFS disk and an administrator PowerShell 5.1 session. From a [`cluster-v*` GitHub release](https://github.com/omnara-ai/omnara/releases?q=cluster-v&expanded=true) that includes Windows assets, download `omnara-windows-amd64.zip` and `omnara-windows-amd64.zip.sha256` into the same directory. Verify and extract them:

```powershell
$expected = (Get-Content .\omnara-windows-amd64.zip.sha256 -Raw).Split(' ')[0]
if ((Get-FileHash .\omnara-windows-amd64.zip -Algorithm SHA256).Hash -eq $expected) {
    Unblock-File .\omnara-windows-amd64.zip
    Expand-Archive .\omnara-windows-amd64.zip -DestinationPath C:\Omnara
    Set-Location C:\Omnara
} else {
    throw 'Windows bundle checksum mismatch'
}
```

The bundle contains `bin` with all five executables, the embedded dashboard, migrations and MCP registry; `deploy/windows` with setup scripts; `WINDOWS-SETUP.mdx` with these instructions; and `SOURCE.txt` identifying the source commit. Go, Node, and a source checkout are not needed. These unsigned POC executables use the fresh-install steps below; the installers do not upgrade existing services.

Tagged release ZIPs also have GitHub build attestations. To verify their provenance with the optional GitHub CLI, run `gh attestation verify .\omnara-windows-amd64.zip --repo omnara-ai/omnara` from the download directory.

For builds ahead of a tagged release, download the `omnara-windows-amd64-bundle` artifact from a successful [push-to-main CI run](https://github.com/omnara-ai/omnara/actions/workflows/ci.yaml?query=branch%3Amain+event%3Apush). GitHub login is required and these artifacts expire after 14 days. Extract the artifact download to obtain the same ZIP and checksum pair, then follow the commands above. Release assets remain available independently of CI artifact retention.

<Accordion title="Alternative: build from source">

Skip the bundle download and extraction above. Start from a separate Omnara checkout. Install Go matching `go.mod`, Node matching `.node-version`, and Corepack (`npm install --global corepack`, then `corepack enable`). From that checkout's root, build a fresh output directory:

```powershell
.\deploy\windows\Build-Windows.ps1 -OutputDirectory C:\Omnara\bin
```

Continue with the native dependencies below. For a source build, run the configuration and service-install commands from the checkout root.

The dependency installer needs `curl.exe` with `--aws-sigv4`. Update curl on older Windows installations if its preflight reports that option missing.

## 2. Configure

Run the remaining commands from `C:\Omnara`, where the bundle was extracted, or from the checkout root for a source build.

Create private setup files and fresh keys. Run this only for a new installation; retain these keys with your backups.

```powershell
. .\deploy\windows\Common.ps1
$setup = 'C:\ProgramData\Omnara\setup'
New-Item -ItemType Directory -Path $setup -ErrorAction Stop | Out-Null
Set-PrivatePermissions $setup
function New-Key {
    $bytes = New-Object byte[] 32
    $rng = [Security.Cryptography.RandomNumberGenerator]::Create()
    try { $rng.GetBytes($bytes) } finally { $rng.Dispose() }
    [Convert]::ToBase64String($bytes)
}
[IO.File]::WriteAllText("$setup\s3-access.txt", 'omnara-poc')
[IO.File]::WriteAllText("$setup\s3-secret.txt", (New-Key))
```

Install Garnet and RustFS as services, substituting your extracted Garnet directory. This creates the `omnara` S3 bucket, verifies authenticated Redis and S3 access, and prints protected credential file paths.

```powershell
.\deploy\windows\Install-Dependencies.ps1 `
  -GarnetDirectory C:\Omnara\garnet\net10.0 `
  -RustFSDirectory C:\Omnara\rustfs `
  -RustFSAccessKeyFile "$setup\s3-access.txt" `
  -RustFSSecretKeyFile "$setup\s3-secret.txt" `
  -WinSWPath C:\Omnara\WinSW-x64.exe

$configuration = [IO.File]::ReadAllText("$PWD\deploy\windows\control-plane.env.example")
$configuration = $configuration.Replace('REPLACE_REDIS_PASSWORD', [IO.File]::ReadAllText('C:\ProgramData\Omnara\dependencies\garnet\config\password.txt'))
$configuration = $configuration.Replace('REPLACE_S3_ACCESS_KEY', [IO.File]::ReadAllText("$setup\s3-access.txt"))
$configuration = $configuration.Replace('REPLACE_S3_SECRET_KEY', [IO.File]::ReadAllText("$setup\s3-secret.txt"))
$configuration = $configuration.Replace('REPLACE_ENCRYPTION_KEY', (New-Key)).Replace('REPLACE_SIGNING_KEY', (New-Key))
[IO.File]::WriteAllText("$setup\control-plane.env", $configuration)
notepad.exe "$setup\control-plane.env"
```

Replace `REPLACE_DATABASE_PASSWORD` with the database password, URL-encoding reserved characters. Leave `OMNARA_PUBLIC_URL=http://localhost:8088` for the SSH-forwarded POC. The file uses literal `KEY=VALUE`, without quotes or shell expansion. The sample enables console email and development mode; development mode also lets `web_fetch` reach loopback, so keep this POC private.

## 3. Install services and IIS

```powershell
.\deploy\windows\Install-Services.ps1 `
  -BinaryDirectory C:\Omnara\bin `
  -FileToolsDirectory C:\Omnara\file-tools `
  -EnvironmentFile "$setup\control-plane.env" `
  -WinSWPath C:\Omnara\WinSW-x64.exe

Install-WindowsFeature Web-Server, Web-WebSockets -IncludeManagementTools
```

Install [URL Rewrite 2.1](https://www.iis.net/downloads/microsoft/url-rewrite), then [Application Request Routing 3](https://www.iis.net/downloads/microsoft/application-request-routing), using their x64 installers. Then run:

```powershell
.\deploy\windows\Configure-IIS.ps1
```

The scripts run migrations once, create separate virtual service accounts, make binaries read-only to services, and create private logs, temporary directories, and a shared case-sensitive memory directory. Services use delayed automatic startup, so allow a few minutes after boot. IIS listens on `127.0.0.1:8088`; dependencies and API listeners also stay on loopback. No firewall rules are opened. These are initial-install scripts: existing services or nonempty data directories are refused. Inspect any reported failure before removing only the failed installation's new services/files and retrying; database migrations are not rolled back.

From your workstation, forward IIS and open `http://localhost:8088`:

```sh
ssh -L 8088:127.0.0.1:8088 <user>@<server>
```

Sign up using the verification link in the protected API logs under `C:\ProgramData\Omnara\control-plane\api\logs`. Add a model provider and API key in the dashboard, create an agent, send a conversation that uses tools, and upload a file. Check that the conversation and file remain after restarting the services.

## 4. Operate the POC

Edit `C:\ProgramData\Omnara\control-plane\config\control-plane.env` for subsequent configuration changes, then restart the affected services. Logs are under each service's `logs` directory. Back up PostgreSQL, the entire memory directory, RustFS data, and the configuration containing encryption keys together.

Memory search and scripted edits use native ripgrep and GNU sed. Windows does not apply Linux Landlock, seccomp, or chroot isolation; GNU sed's restricted mode and process lifetime/output limits still apply. These tools have the worker account's filesystem access. Startup failures produce a warning. A failed edit check disables scripted edits until you fix the executable/DLL setup and restart `omnara-worker`; searches check availability on each call.

WinSW 2 does not provide a Windows preshutdown hook. Before a planned reboot, stop Omnara and its wrapped dependencies explicitly so the worker can drain:

```powershell
Stop-Service omnara-worker, omnara-api, omnara-maintenance
Stop-Service omnara-garnet, omnara-rustfs
Restart-Computer
```

This page describes a private POC. Use the [configuration reference](/self-hosting/configuration) when planning public URLs, TLS, email delivery, or an existing Redis/S3 service.
