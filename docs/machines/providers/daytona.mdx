[Daytona](https://www.daytona.io) is secure and elastic infrastructure for running AI-generated code. Connect your Daytona organization with a custom pool.

## Why Daytona

- **Lightning-fast sandboxes.** Daytona creates a sandbox in under 90 ms, from code to execution.
- **Isolated runtime protection.** Each machine is its own sandbox, separated from your infrastructure, so AI-generated code runs isolated from your systems.
- **Massive parallelization.** Run many sandboxes side by side for concurrent agent workflows.
- **Your existing Docker images.** Build snapshots from any tagged registry image or Dockerfile, including private images on Docker Hub, GitHub, Google Artifact Registry, and Amazon ECR. Start from a Docker-in-Docker image, and agents can run `docker compose` stacks right inside their machine.
- **Work alongside your agents.** Open a web terminal from the Daytona dashboard, or connect over SSH from your own editor, to look at an agent's files and processes or lend a hand.

## Set up a Daytona pool

<Steps>
  <Step title="Create an API key">
    In the [Daytona dashboard](https://app.daytona.io/dashboard/keys), click **Create Key** and give it the `write:sandboxes` and `delete:sandboxes` permissions. Store the key as an org-owned [secret](/organization/secrets) in Omnara.
  </Step>
  <Step title="Choose or build a snapshot">
    Daytona's default `daytona-medium` snapshot (2 vCPU, 4 GiB) works as is.

    To build your own, start from an image with a pinned tag that meets the [custom image requirements](/machines/providers/overview#custom-image-requirements), and set its size:

    ```bash
    daytona snapshot create omnara-agent --dockerfile ./Dockerfile --cpu 2 --memory 4 --disk 10
    ```

    Wait until the snapshot is **Active** in the region you plan to use. For private registry images, add the registry in the Daytona dashboard first.
  </Step>
  <Step title="Create the pool">
    On the **Machines** page, click **New pool** and choose **Daytona**. Enter the credential, snapshot name, target, CPU and memory maximums, and capacity limits. The maximums must be at least the snapshot's size.

    To use the API instead, call [Create a pool](/machines/pools#create-a-pool) with the fields in the [configuration reference](#configuration-reference).
  </Step>
</Steps>

## Configuration reference

`provider_config`:

| Key | Required | Description |
| --- | --- | --- |
| `api_base_url` | No | Daytona API base URL. Defaults to `https://app.daytona.io/api`. |
| `allowed_snapshots` | No | [Allowlist](/machines/providers/overview#allowlists) for `snapshot`. |
| `allowed_targets` | No | [Allowlist](/machines/providers/overview#allowlists) for `target`. |

`default_machine_provider_options`:

| Key | Required | Description |
| --- | --- | --- |
| `snapshot` | Yes | Snapshot name. Snapshot IDs aren't accepted. |
| `target` | Yes | Region: `us` or `eu`. For a custom region, use its ID from the Daytona dashboard. |
| `startup_script` | No | Shell script that runs on each new machine before the daemon starts. |

Pools require CPU and memory maximums. Defaults are optional because the snapshot sets each machine's size, and that size counts against the pool and project limits.
