Connecting a BYO machine is three moves: create the machine record, run a daemon on the computer, and grant the machine to the projects that should use it. The console's **Connect a machine** dialog does all three in one flow; the API exposes each piece so you can automate it.

## Create the machine record

A machine starts as a record in the control plane — the daemon attaches to it later.

<Tabs>
<Tab title="Console">
  Open **Machines** in the sidebar and click **Connect machine**. In the **Connect a machine** dialog, set the machine name — this is what agent configs reference as `machine_name`, so pick something stable — and optionally attach **Project grants**. Click **Connect machine**; the next screen is the daemon install step below.
</Tab>
<Tab title="API">
  ```bash
  curl "$OMNARA_API/orgs/$ORG/machines" \
    -H "Authorization: Bearer $OMNARA_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "display_name": "build-server-1",
      "description": "Bare-metal builder in the office rack",
      "cwd": "/srv/repo",
      "env": { "CI": "true" },
      "secret_env": { "GITHUB_TOKEN": "sec_7jehcyd5n6a2bfgik7mv4qtrwz" }
    }'
  ```

  ```json
  {
    "id": "mch_5n6a2bfgik7mv4qtrwz3jehcyd",
    "org_id": "org_k7mv4qtrwz3jehcyd5n6a2bfgi",
    "source_kind": "byo",
    "machine_pool_id": null,
    "display_name": "build-server-1",
    "description": "Bare-metal builder in the office rack",
    "provider": "byo",
    "lifecycle_state": "active",
    "connection_state": "offline",
    "cwd": "/srv/repo",
    "env": { "CI": "true" },
    "secret_env": { "GITHUB_TOKEN": "sec_7jehcyd5n6a2bfgik7mv4qtrwz" },
    "...": "..."
  }
  ```

  `display_name` is what agent configs reference as `machine_name`, so pick something stable. `cwd`, `env`, and `secret_env` are execution defaults for every process on this machine; `secret_env` injects [secret](/organization/secrets) values by `sec_…` reference at process launch, so credentials never sit in the machine record.
</Tab>
</Tabs>

## Install the daemon

The daemon uses a **machine token** to connect. It has the versioned
`omnara_daemon_v1_<secret>_<checksum>` shape and is shown only once when
created. The final six characters detect copy/paste mistakes; they are not a
replacement for keeping the whole token secret.

<Tabs>
<Tab title="Console">
  The **Connect a machine** flow creates a token and shows it alongside the install command.
</Tab>
<Tab title="API">
  Create a token for the machine:

  ```bash
  curl -X POST "$OMNARA_API/orgs/$ORG/machines/mch_5n6a2bfgik7mv4qtrwz3jehcyd/daemon-tokens" \
    -H "Authorization: Bearer $OMNARA_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{"name": "build-server-1"}'
  ```

  The response includes the plaintext `token` and its metadata in `token_record`. Store the token now; later API responses return only its metadata.
</Tab>
</Tabs>

```sh
curl -fsSL https://app.omnara.com/install/omnarad.sh | sh
```

The installer supports macOS and Linux on amd64 and arm64. It prompts for the token, installs `omnarad` under `~/.omnarad`, and registers it as a user service using systemd on Linux or launchd on macOS. The daemon connects outbound and updates itself. Manage it with `omnarad start|stop|restart|status`.

Once the daemon connects, the machine appears online.

## Grant the machine to a project

Machines are org-level; a project's agents can only target machines granted to that project.

<Tabs>
<Tab title="Console">
  If you didn't grant the machine while connecting it, find its row under **Machines**, click **Grant to project**, and select the project.

  From a project, open **Grants**, select the **Machines** tab, and click **Grant machines**. This tab also lists existing grants; click **Delete grant** to revoke one.
</Tab>
<Tab title="API">
  ```bash
  curl "$OMNARA_API/orgs/$ORG/projects/$PROJ/machine-grants" \
    -H "Authorization: Bearer $OMNARA_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{"machine_id": "mch_5n6a2bfgik7mv4qtrwz3jehcyd"}'
  ```

  ```json
  {
    "grant": {
      "id": "pmg_6a2bfgik7mv4qtrwz3jehcyd5n",
      "machine_id": "mch_5n6a2bfgik7mv4qtrwz3jehcyd",
      "source_kind": "explicit",
      "...": "..."
    },
    "...": "..."
  }
  ```

  Revoking the grant stops that project's work on the machine but leaves the machine itself untouched. Grants created through a [pool grant](/machines/pools) are managed through the pool and cannot be revoked individually.
</Tab>
</Tabs>

With the grant in place, configs in that project can reference the machine:

```yaml
machine_sources:
  - machine_name: build-server-1
    cwd: /srv/repo
```

## Manage a machine

The console's **Machines** page shows every machine you can access. The org API provides the same view and explains whether access comes from your org role, having created the machine, or a project grant. The project API lists only machines that project's agents can use.

You can update `cwd`, `env`, and `secret_env` through the API; machine names cannot be changed.

Machine tokens can be created, listed, and revoked through the API.

Deleting a BYO machine disconnects its daemon, revokes its tokens, removes its grants, and releases its agent bindings. In the console, open the machine's row menu and click **Delete**.
