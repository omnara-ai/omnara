Create a Slack app from your project's **Apps** page. Your Omnara app owns the
Slack setup and credentials. Its launcher, tools, listener and interaction handler
can be used independently; see [Apps](/integrations/apps).

## Connect Slack

Save an app with definition `omnara.slack` and a name such as `engineering`.
Connect an existing Slack app, or let Omnara create the Slack registration using
an app configuration token from [Slack's app settings](https://api.slack.com/apps).
The bot token obtained through OAuth represents the bot's access to that workspace;
it is different from the configuration token used to create the registration.

With the CLI or API, create the Omnara app first:

```json
{"name":"engineering","definition_id":"omnara.slack","settings":{}}
```

Submit that body to `POST /orgs/{orgID}/projects/{projectID}/apps`, then use its
returned `app_…` ID for setup. To create a Slack registration:

<SlackCreateApp />

For an existing Slack registration:

<SlackExistingApp />

Configure the returned `events_url`, `actions_url` and `redirect_uri` in Slack.
Open `oauth_url` before `expires_at`, signed in to Omnara as the user who started
setup, and approve installation. The CLI opens this link unless `--no-browser`
is supplied. The app becomes active when its `last_oauth_flow_id` matches the
returned flow. Setup updates that specific saved app and does not create a launcher.
For self-hosting, `OMNARA_PUBLIC_URL` must be a public HTTPS origin.

Reauthorizing creates a new encrypted project secret and updates the app to use
it. A superseded secret remains in Secrets until you delete it; Omnara prevents
deletion while another resource still references it. Disconnecting preserves
the credential reference for reconnect, while deleting the app releases it.

## Start agents from mentions

Choose profiles and a workspace or channel scope in the app's launch settings.
With one profile, a mention starts an agent in that thread. With several, the
first reply asks which profile to use; no agent starts before the selection.
Anyone in the conversation can choose. Menus expire after an hour, and follow-up
messages sent before the choice may be missed. Edit offered profiles for future
requests without changing existing conversations.

A launch derives a config with read/post tools, a thread listener and a Slack
interaction handler. Existing explicit config entries are preserved. Thread
replies steer the selected agent and cancel its outstanding interactions. Bot
messages are ignored. Overlapping launchers using the same bot are discouraged.

For API setup, add this `settings.launcher` to the app's create/update body:

```json
{
  "trigger":"mention",
  "scope_kind":"channel",
  "scope_ref":"C123",
  "slots":[{"key":"assistant","agent_profile_id":"aprf_aeaqcaibaeaqcaibaeaqcaibae"}]
}
```

Use `scope_kind: "workspace"` and the Slack workspace ID for workspace-wide
mentions. Keep slot keys stable when editing.

## Scheduled threads

Use **Add schedule** on the app page to post a template opening message and launch
one profile in its new thread. The tools, reply listener and interaction handler
are ready when the agent starts. Schedules can coexist with mention launches.
See [scheduled app launches](/integrations/apps#start-a-new-thread-on-a-schedule)
for setup, template variables and recovery behavior.

## Use tools without a launcher

```yaml
tools:
  app__engineering__read:
    config: {channel_id: C123}
  app__engineering__post_message:
    config: {channel_id: C123}
listeners:
  engineering__thread_messages:
    config: {}
```

This agent can read and post in `C123`, but receives no messages initially. A
post with `follow_replies: true` subscribes it to the confirmed conversation.
To subscribe immediately, put typed addresses in the listener's
`config.conversations`, for example `{channel_id: C123, thread_ts: "111.222333"}`.
Removing the sending tool leaves these subscriptions intact; removing the
listener stops them all.

`read` accepts `cursor` and `limit`. `post_message` accepts `text` and up to 20
`artifact_ids`. Destination fields not fixed in config are supplied as model
arguments; fixed fields cannot be overridden. Fix `thread_ts` alongside
`channel_id` to keep a tool in one thread. For files in a new followed thread,
post text first, then attach files in that thread.

Add `interaction_handlers.engineering.config` with an optional fixed channel and
thread to offer Slack questions and approvals. The model can choose the handler
with `set_interaction_handler`; incoming messages from a matching conversation
also select it automatically. The dashboard always remains available.
