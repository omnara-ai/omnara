Connect your Slack app once, then choose which agents may read, send, receive
replies or present approvals. These are separate [app capabilities](/integrations/apps).

## Connect a workspace

In the dashboard, open **Apps** under your project, choose **Add app**, then
**Slack**. Connect an existing Slack app or let Omnara create one. OAuth saves a
project connection and returns you to setup; it does not create a launcher yet.
Choose your app name, offered profiles and capabilities, then save the app.
You can also save capabilities without an automatic launcher or profile.

For CLI setup, first create an [agent profile](/agents/configuration#profiles)
whose model supports tools. The profile must not explicitly disable
`slack_post_message`.

To let Omnara create the Slack app, obtain an app configuration token from
[Slack's app settings](https://api.slack.com/apps), then run:

<SlackCreateApp />

Open `oauth_url` before `expires_at`, signed in to Omnara as the user who started
setup, and approve the workspace installation. The CLI opens the link unless
you pass `--no-browser`. Each setup creates a new Slack app; run it once per bot.

For an existing Slack app, supply its credentials instead:

<SlackExistingApp />

Configure that app with the returned `events_url`, `actions_url` and
`redirect_uri` before completing OAuth. For self-hosting, `OMNARA_PUBLIC_URL`
must be a public HTTPS origin. Slack's [Events API setup](https://docs.slack.dev/apis/events-api/)
explains event subscriptions and bot access to conversations.

The profile-based CLI setup creates a project connection and a project app. The app has a
workspace mention launcher for the selected profile, with `slack_read`,
`slack_post_message`, a `message` listener and the Slack interaction handler.
The base profile config is unchanged.

List `/integration-connections?oauth_flow_id={flow_id}` under the project API path
to find the resulting `iin_…` connection. List `/apps` to inspect or edit the
saved launcher. Connection access and launcher behavior are managed separately.

## Configure an existing agent

Add this fragment to its [config](/agents/configuration), using your connection
ID and Slack channel ID:

```yaml
app_resources:
  release_channel:
    definition: omnara.slack
    connection: iin_aeaqcaibaeaqcaibaeaqcaibae
    scope:
      slack: {channel_id: C123}
    tools:
      slack_read: {}
      slack_post_message: {}
    follow: {replies: true}
```

This agent can read and post in the channel, but does not receive all channel
messages. A successful `slack_post_message` call with `follow_replies: true`
registers replies to that posted conversation. Posting files into a new followed
thread requires posting the text first, then attaching files in that thread.

For a fixed thread, add `thread_ts: "111.222333"` to the Slack scope. Add
`listener: {events: [message]}` to receive messages in the selected scope. Add
`interaction_handler: {definition: omnara.slack.interactions}` to make it an
eligible destination for questions and approvals. Each addition is independent.

`slack_read` supports `thread_ts`, `cursor` and `limit`. `slack_post_message`
accepts `text`, optional `thread_ts`, and up to 20 `artifact_ids`. Both take a
`resource` selector when needed. Tool arguments cannot escape the configured
channel or fixed thread. Ordinary model output remains in Omnara.

## Customize a launcher

To launch a profile only from mentions in one channel, submit this body to
`POST /orgs/{orgID}/projects/{projectID}/apps`. Replace the example IDs. If setup
already created a launcher for the same bot/profile, update that app with `PUT`
instead of creating overlapping launchers.

```json
{
  "name": "release-assistant",
  "settings": {
    "resource": {
      "definition": "omnara.slack",
      "connection": "iin_aeaqcaibaeaqcaibaeaqcaibae",
      "tools": {"slack_read": {}, "slack_post_message": {}},
      "listener": {"events": ["message"]},
      "interaction_handler": {"definition": "omnara.slack.interactions"}
    },
    "launcher": {
      "trigger": "mention",
      "scope_kind": "channel",
      "scope_ref": "C123",
      "slots": [{"key": "assistant", "agent_profile_id": "aprf_aeaqcaibaeaqcaibaeaqcaibae"}]
    }
  }
}
```

With one profile, the first mention launches an agent scoped to its thread.
With several profile slots, the bot replies with a selection menu in that thread.
Anyone with access to the conversation can choose; only the selected profile
launches, retaining the original message and author. Choose a profile before
sending follow-up messages; earlier follow-ups may be missed.
Menus expire after one hour. Mention again if the menu expires or its offered
profile has been removed. Attachments are checked against their original content;
if Slack can no longer supply that content, the request fails visibly in event recovery.

Open **Edit settings** on the saved app to add or remove offered profiles without
creating another Slack app. API clients can update the launcher's `slots` while
preserving stable keys. The profile-based CLI flow initially offers the selected profile;
edit the saved app afterward to offer more. Editing the list leaves existing
conversations with their original agents.

The declared listener handles later replies without another mention. The default OAuth launcher uses
workspace scope and also handles DMs, keeping one conversation per DM. Human
Slack messages steer the agent and cancel its open interactions. A question or
approval can be answered in Slack or the dashboard.

Removing a project app stops its launcher and retains existing agents and the
connection. Disable or delete the connection to revoke provider access; uninstall
the bot separately in Slack if needed. Existing deployments must follow the
[cutover runbook](/self-hosting/composable-apps-cutover): old thread listeners are
reset, while eligible agents retain scoped sending and their histories.
